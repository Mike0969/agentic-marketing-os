# REVIEW-RUBRIC.md — plan review criteria

> DRAFT — generated by the orchestrator because ROUTING.md references this file and it did not exist. Edit freely; the reviewer challenges PLAN.md against exactly what's written here.

the reviewer's job is adversarial: assume the plan is wrong and try to prove it. every finding gets a severity tag: **blocker** (plan fails if unaddressed), **major** (likely rework downstream), **nit** (style/clarity).

## 1. spec integrity
- is the problem statement unambiguous? could two competent engineers read it and build different things?
- are all terms defined? any "handle X properly" or "robust Y" without a testable definition is a finding.
- unstated assumptions: what does the plan take for granted about the environment, data, versions, auth, or existing code? list each one.

## 2. interfaces
- are all interfaces frozen and written out (signatures, types, formats, error shapes)?
- do the interfaces of adjacent tasks actually match — producer output vs consumer input, field by field?
- does anything depend on an interface the plan doesn't control and hasn't verified exists?

## 3. task DAG
- is every task self-contained per the HANDOFF rules (description, acceptance criteria, file paths + signatures, must-not-touch, test command)? a task missing any of the five is a blocker.
- are dependencies explicit and acyclic? can lanes actually run in parallel without touching each other's files?
- is any task too big to fail cheaply? tasks should fail in minutes, not hours.

## 4. acceptance criteria
- can each criterion be verified by running the stated test command — no human judgment required?
- would the criteria pass on a wrong-but-plausible implementation? (weak criteria are majors.)
- does any task fail its own acceptance criteria as written?

## 5. edge cases & failure modes
- empty/null/malformed inputs, concurrency, ordering, retries, partial failure, idempotency — which apply and which does the plan ignore?
- what happens when an external dependency (API, CLI, model endpoint) is down, slow, or returns garbage?

## 6. scope
- anything in the plan not required by the spec? (speculative flexibility is a major.)
- anything required by the spec but missing from the DAG?

## output format
one finding per line: `[blocker|major|nit] <section> — <one-sentence finding> — <what would fix it>`
