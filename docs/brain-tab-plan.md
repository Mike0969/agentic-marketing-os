# PLAN — Brain tab (embed the business-brain knowledge graph in the OS)

Feature: a "Brain" tab in the agentic-marketing-os dashboard that shows the cross-venture knowledge graph generated by graphify over `~/Claude Folder/business-brain`. Read-only visual; additive; no change to the marketing loop.

## Spec

The graph is a self-contained HTML (`business-brain/graphify-out/graph.html`, ~342 KB) EXCEPT it loads `vis-network` from a CDN (`unpkg.com`) with SRI — that is graphify's output, inherited as-is for v1. We copy that HTML into this app's `public/` as a committed snapshot (so it deploys on Vercel, where the business-brain repo is not present at build time) and embed it in an iframe under a new `/brain` route.

Out of scope: regenerating/modifying the graph, live cross-repo reads at runtime, removing the CDN dep, auth changes.

### Environment facts (verified 2026-07-12)

- Nav lives in `components/os/os-shell.tsx` as `const nav = [{href,label,icon}...]` (Home, Marketing, Sales, Agents, Settings); icons from `lucide-react`.
- `(shell)` routes are admin-gated by middleware; a new page under `app/(shell)/` inherits that gate. No new auth.
- Static files under `public/` are served at the site root (`public/brain/graph.html` → `/brain/graph.html`).
- `middleware.ts` — must be checked for a Content-Security-Policy that would block the iframe or the unpkg script; if a CSP exists, note whether `/brain/graph.html` (same-origin iframe) and `unpkg.com` (script-src) are allowed. If no CSP is set, nothing to change.
- Supabase is back and connected (real data); the app is AUTONOMOUS again.

## Frozen interfaces

### 1. `scripts/sync-brain-graph.mjs` + `npm run brain:graph`
- Source: `process.env.BUSINESS_BRAIN_DIR ?? path.join(process.cwd(), "..", "business-brain")`, then `/graphify-out/graph.html`.
- Dest: `public/brain/graph.html`; also write `public/brain/meta.json` = `{ syncedAt: ISO, source: <abs path> }`.
- Behavior: `mkdir -p public/brain`; if source file missing → print a clear message naming the expected path and exit 1 WITHOUT writing graph.html (a stale snapshot is better than an empty one); else copy bytes, write meta.json, print `synced <bytes> bytes`, exit 0. Idempotent.
- Writes nothing outside `public/brain/`.

### 2. `app/(shell)/brain/page.tsx` (server component)
- Reads `public/brain/graph.html` existence via fs at request time (`export const dynamic = "force-dynamic"`).
- Present → `PageHeading` ("Brain", subtitle naming the cross-venture graph + last-synced from meta.json) and a full-height iframe `src="/brain/graph.html"` (`title`, `className` giving a tall panel, `sandbox="allow-scripts allow-same-origin"` so the vis-network script runs).
- Absent → an `OSPanel` explaining it isn't synced yet and to run `npm run brain:graph` (no crash).

### 3. Nav
- Add `{ href: "/brain", label: "Brain", icon: Brain }` (lucide `Brain`) to the `nav` array in `os-shell.tsx`, after Agents.

### 4. Committed snapshot
- Commit `public/brain/graph.html` + `public/brain/meta.json` so the tab works on Vercel. Refresh = re-run `npm run brain:graph` and commit.
